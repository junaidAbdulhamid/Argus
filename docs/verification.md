# Verification record

The implementation is checked with portable API tests, real PostgreSQL API/concurrency tests, React interaction tests, and Chrome browser workflows. Commands are in the root README.

- API tests cover authentication, invalid/expired tokens, roles, tenant isolation, project CRUD, idempotent ingestion, atomic batch rollback, ordered and immutable trajectories, priority claiming, assignment ownership, duplicate requests, expiration recovery, annotation drafts/completion, independent review, audit events, and cascading deletion.
- PostgreSQL tests run concurrent requests from eight annotators and four simultaneous requests from the same annotator, checking distinct task ownership and idempotent resumption.
- Redis tests exercise atomic sorted-set priority hints and safe outage fallback.
- Frontend interaction tests cover pagination boundaries, tabs, retry actions, JSON validation, draft updates, unsaved-change protection, and submission to review.
- Browser tests inspect the seeded dashboard and trace at desktop/mobile sizes, then create an isolated workflow and complete annotation and independent approval through the UI.
- Infrastructure checks build both images, verify service health, validate Compose configuration, and apply/check/roll back/reapply the PostgreSQL migration in a disposable database.

Screenshots are generated by browser tests rather than mockups. Counts reflect the actual seeded database at capture time.
